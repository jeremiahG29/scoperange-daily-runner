# Security

Report a vulnerability through GitHub's private vulnerability reporting interface for the future repository. Do not include credentials, private source, customer information, or production details in a public issue.

The registered reusable-workflow shell is provider-disabled, grants no token permissions, accepts no caller data or secrets, and unconditionally skips its sole job. This inert scaffold has no credential, target, connection, execution, or activation authority. Workflow enablement and any later security contact channel require separate review.

The non-registered candidate accepts an exact public commit only through an external post-merge governance binding. That binding, the durable recurrence adapter, production identity, exact target, and writer remain unconfigured. Its zero-effect receipt uses an allowlisted schema and reason vocabulary so configuration or failure text cannot be reflected into public logs.

Synthetic source and recurrence adapters are test-only control-plane components. The source adapter is restricted to local Git object inspection and returns no source bytes, paths, or commit identifiers. The recurrence adapter uses only shared in-memory fixture state. Neither component is imported by the entry point, registered workflow, or inactive workflow candidate, and neither has credential, network, provider, production, ingestion, promotion, or pricing authority.

Synthetic identity receipts and target capabilities use ephemeral test keys and real Ed25519 signature verification, bounded lifetimes, opaque output, and shared in-memory replay fixtures. They cannot configure GitHub OIDC, trust a provider, select a production target, exchange a token, connect a writer, or reach a network. The target capability authorizes only a synthetic evidence-envelope submission and explicitly denies pricing, promotion, and live-price authority.

The production-connection contract is disabled by construction. Raw targets, connection strings, keys, identity tokens, and other connection-shaped input produce the same fixed zero-effect rejection without reflection. Any real identity, target mapping, ingress broker, connection, or writer requires a separate security review and explicit authorization.
